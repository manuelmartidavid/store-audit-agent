## 4. The makerlab bug — diagnosed, not a crawler defect

```
declared origin : https://makerlab-electronics-ph.myshopify.com
actual final url: https://www.makerlab.ph/
same_origin?    : False
```

The store 301s to its primary custom domain. `_template_status` returns `absent`
for anything landing off the declared origin — **the guard working correctly** — so
zero templates captured, and `_overall_status` reported `blocked` with `block:
null` and six HTTP 200s. Lighthouse then had nothing to audit.

The runbook's command was wrong, and is now corrected with a warning. **Any Shopify
store with a custom domain redirects away from its `.myshopify.com` address.**

There is a latent reporting weakness worth considering but *not* yet acted on: a
crawl that is 100 % off-origin redirects reports as `blocked` with `block: null`,
which is self-contradictory and reads as bot-blocking rather than operator error.
Making that its own status, or recording the redirect as the block evidence, is a
real design question — **do not fix it casually.**

never clobber its predecessor. Not yet implemented.

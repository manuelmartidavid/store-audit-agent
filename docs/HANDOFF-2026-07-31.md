
The store 301s to its primary custom domain. `_template_status` returns `absent`

null` and six HTTP 200s.

`platform: shopify` on seven evidence signals, 7 apps. The runbook command is
corrected, and the warning is now also in entry 03's `context.yaml` header where
whoever recaptures it will actually be looking.

**Any Shopify store with a custom domain redirects away from its `.myshopify.com`
address.**

There is a latent reporting weakness worth considering but *not* yet acted on: a
crawl that is 100 % off-origin redirects reports as `blocked` with `block: null`,
which is self-contradictory and reads as bot-blocking rather than operator error.
Making that its own status, or recording the redirect as the block evidence, is a
real design question — **do not fix it casually.**

## 5. What was lost, and the fix that is now real

**`b219afac…` still no longer exists anywhere.** The recapture replaced
`fixtures/02-sabotaged`, and the archive step wrote `archives/02-sabotaged.tar.gz`
— the same filename that held the old frozen fixture. Decision 19 limits the
damage — *the commitment is the manifest hash, not the capture bytes* — and the
labels and run JSONs are intact, so this is lost **auditability**, not lost
results. The 18 recorded runs can be verified against the recorded hash only.

**The process fix is now implemented, in three layers:**

1. **Names are stamped** `<entry>-<crawler_version>-<manifest_sha12>.tar.gz`. The
   crawler version alone does not close the hole — re-freezing the same fixture
   under the same version still collides — so the manifest short hash carries the
   uniqueness, and any collision that does occur is byte-identical and harmless.
2. **`crawler.archive` refuses to overwrite.** `archive()` raises unless
   `--force` is passed. Covered by three tests in `tests/test_archive.py`,
   including one that reproduces the b219afac loss directly.
3. **Runbook phase 4.1** is a loop that derives the short hash and skips rather
   than overwrites an existing target.

All five archives were renamed to the stamped scheme and **each name was verified
against its own tarball's embedded manifest hash**, not against the table above —
they agree, so no archive has drifted from the capture it claims to hold.

> 🔴 **`archives/` is gitignored (`.gitignore:40`).** None of this is in git. The
> stamped tarballs exist **only on this machine**, which is the same exposure that
> made the b219afac loss permanent. Stamping stops a re-freeze from clobbering a
> predecessor; it does nothing about disk failure. Copying `archives/` off-box is
> still manual and still nobody's assigned job.

The invalid first makerlab capture is kept as
`archives/makerlab-INVALID-off-origin-20260731.tar.gz` — it is the only artefact
of the off-origin failure mode. Delete it freely.
